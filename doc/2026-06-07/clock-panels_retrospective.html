1. 背景与目标

从一个问题起步:"polybar 左边那个 rofi 启动图标怎么实现的"。顺势把 polybar 正中的时钟模块做成可交互: 左键开控制中心、右键开音乐面板。音乐源为 Spotify / 浏览器网页(MPRIS),机器仅有 playerctl,故面板定位为遥控器。 用户要 iOS 颜值,遂用 gjs+GTK3 自绘。

3. 关键问题与根因(踩坑实录)

#现象根因修法
1 左键时钟先是切日期格式;移除 alt 后变成完全没反应 polybar 3.7.1 的 internal/date 不认 config 级 click-left。有 date-alt 时它发自己的内层 toggle 动作(遮蔽外层 click);去掉 alt 后 config click 干脆不触发 绕开 config,把动作标签直接写进 label:
%{A1:cmd:}…%{A3:cmd:}…%{A}%{A}。这与那个"能触发的 toggle"同一机制
2 左键先在屏幕正中弹一个空白悬浮窗,再跳到时钟下 启动顺序是 show_all() → 定位 → 填内容:窗口先以 WM 默认位置(i3 居中)映射、且内容未填 改为先 refresh() 填内容 + get_preferred_size 计算并 move() 定位,再 show_all()
3 音乐面板 🔁 循环键永远只切到 None 串联 sed -e s/None/Track/ -e s/Track/Playlist/ -e s/Playlist/None/ 会级联,任何输入最终都变 None 点击时读当前 loop,在 JS 里算下一态再 set;不要用链式 sed 推进状态
4 控制中心"有点丑",与桌面割裂 control-center.rasi 在 5-31 切米色时漏迁移,仍停在老水墨暗色/金黄 按 beige 色板重写,对齐主启动器 config.rasi 风格
5 验证 toggle 时 pgrep 报"还在",实则已关 pgrep -f "…music-panel.js" 把测试命令自身的 zsh 包装行(含该字符串)也匹配了 —— 自我匹配 验证逻辑写进独立脚本文件,改用 /proc/*/cmdline 扫描计数

4. 经验教训

  1. 不要假设 polybar 内置模块支持 config 级 click。 internal/date 在 3.7.1 不认 click-left/right;通用做法是 custom/* 模块,或在 label/format 里手写 %{A} 动作标签。判定"点击有没有触发"用不可能因环境失败的命令(如 touch)做埋点,一次点击即可证伪。
  2. gjs+GTK3 是这台机器上做 iOS 风桌面组件的正解,不是 eww。 机器无 rust/eww 且 eww 需现编;gjs(灵动岛已在用)+ GTK3/GdkPixbuf 视觉能力同级、零新依赖。复用既有技术栈让第二个 gjs 程序(控制中心)一次跑通、零 API 修正。
  3. GTK 弹窗要"先填内容+先定位,再 show",否则会有居中空白闪框。
  4. 状态机别用链式 sed 推进(会级联);在代码里读当前态算下一态。
  5. "改配色各组件要同步"是真会被违反的(rasi 漏迁移)。新增/改主题时应对照组件清单逐一核对。
  6. 进程开关用精确特征 pgrep -f "gjs .*<name>.js",避免误杀灵动岛 notification-daemon.js 或其它 gjs;验证时警惕 pgrep 自我匹配。
  7. 子-agent 驱动开发对"代码已在计划里写全"的机械任务很顺,但控制器侧的代码审查仍是关键质量闸 —— 真正的逻辑 bug(#3 循环键)是审查时抓到的,不是冒烟测试。
